# Контракты инструментов · ДЗ1

Имена начинаются с действия; схемы предоставляются модели из Pydantic и проверяются теми же моделями **в коде**. Доступ к счету берётся из `Session.account_id`, а не из параметров вызова.

## 1. `get_spending_summary`

| Поле контракта | Значение |
|---|---|
| Имя | `get_spending_summary` |
| Описание | Расходы за период и необязательную категорию, разбивка и число операций. Не искать подписки. |
| Аргументы | `date_from`, `date_to` в `YYYY-MM-DD`, обязательны; `category` — `taxi`, `food`, `transfer`, `subscription`, `other` или не указана. Начало не позже конца. |
| Не выбирает модель | `account_id`, путь выписки, итоговые суммы |
| Результат | `period`, `total_rub`, `operations_count`, `by_category` |
| Ошибки | `validation` (схема), `not_found`, `timeout`, `internal` |
| Тип / надёжность | чтение, три технические попытки, задержка 0,5 и 1 с, таймаут каждой попытки 3 с |
| Отказ / права | изоляция счета через Session; лишнее поле `account_id` запрещено |

**Семантика синтетических данных:** положительное значение в `amount_rub` означает расход, отрицательное — поступление. Суммы агрегируются через `Decimal` и сериализуются в рублях. Это не онлайн-баланс.

## 2. `find_recurring_payments`

| Поле контракта | Значение |
|---|---|
| Имя | `find_recurring_payments` |
| Описание | Поиск вероятных регулярных расходов и возможных дублей. Не считать общую сумму расходов за период. |
| Аргументы | `min_months` — целое от 2 до 12, по умолчанию 3 |
| Не выбирает модель | `account_id`, рассчитанные `subscription_id` |
| Результат | `recurring` (`subscription_id`, `merchant`, `amount_rub`, `months`, `last_date`), `possible_duplicates`, количества найденных записей |
| Ошибки | `validation`, `timeout`, `internal` |
| Тип / надёжность | чтение, три попытки при таймауте, до 50 объектов в каждом списке |
| Отказ / права | только текущий счёт из Session; платежи других счетов не выдаются |

**Эвристика:** одинаковый продавец и сумма в `N` разных месяцах. Возможные дубли — совпадающие продавец, сумма, дата. Результат — гипотеза для проверки человеком, не доказательство ошибки банка.

## 3. `flag_subscription`

| Поле контракта | Значение |
|---|---|
| Имя | `flag_subscription` |
| Описание | Локально пометить найденную подписку к отмене. **Не отменяет реальное списание**. |
| Аргументы | `subscription_id` — строка вида `sub_` и восемь hex-символов из результата поиска |
| Не выбирает модель | счёт, подтверждение человека, идентификация исходной серии |
| Результат | `status=flagged`, `merchant`, `amount_rub` или `cancelled` |
| Ошибки | `validation`, `not_found`, `timeout`, `internal` |
| Тип / надёжность | действие; ни одного автоматического повтора; `set` обеспечивает идемпотентную пометку |
| Отказ / права | без подтверждения конкретных параметров возвращает `cancelled`, состояние не меняется |

## Формат ошибки

```json
{
  "error": {
    "type": "timeout",
    "message": "Сервис операций не ответил",
    "hint": "Предложи клиенту оператора"
  }
}
```

Проверка схемы, лимитов, прав и подтверждения выполняется кодом, независимо от поведения модели. `merchant` и другие поля загруженных операций считаются недоверенными данными; текст назначения платежа не является инструкцией для выполнения действий.
